phux is a Cargo workspace. Only `phux-protocol` is intended for publication; the rest are `publish = false`.

| Crate | Purpose |
| --- | --- |
| `phux` | Single binary; `attach`, `server`, and headless agent verbs |
| `phux-protocol` | Wire types, codec, version negotiation; publish-ready |
| `phux-core` | Domain types: in-process terminal registries |
| `phux-server` | Daemon: per-terminal actor, PTY supervision, output fanout |
| `phux-client` | Client library + reference TUI; also the SDK that `phux-mcp` and the CLI agent verbs link against |
| `phux-mcp` | MCP adapter exposing the agent verb set as MCP tools |
| `phux-config` | TOML config schema \\+ status widget contract |

## In-tree details

- **`phux-protocol`** — length-prefixed positional frame codec (per `docs/spec/appendix-encoding.md`); `HELLO` / `ATTACH` / `DETACH` / `TERMINAL_OUTPUT` / `TERMINAL_SNAPSHOT` / `INPUT_*` / `BELL` / `ERROR` / `PING` subset of the message catalog plus the `KILL_TERMINALS` atomic group-teardown command (ADR-0030); structured input types re-export libghostty's atoms directly (ADR-0008). Currently at `PROTOCOL_VERSION 0.3.0`.
- **`phux-core`** — slotmap registries for in-process domain objects mapping to L1 terminals; grouping is L3 metadata, not a wire tier (ADR-0030).
- **`phux-server`** — tokio current-thread runtime; UDS listener at `$XDG_RUNTIME_DIR/phux/phux.sock`; per-terminal actor (ADR-0014) that owns a `libghostty_vt::Terminal` and a real PTY child; per-terminal input encoders (ADR-0006); broadcast output fanout; snapshot synthesis from `RenderState`; per-client capability rewriter for outbound bytes.
- **`phux-client`** — the SDK library and the reference TUI. As a library it wraps the `phux-protocol` codec and exposes terminal resolution, snapshot, run, and wait functions; `phux-mcp` and the CLI agent verbs both link against it. As the TUI it runs the UDS attach loop, raw-mode/altscreen guard, stdin keyboard parser, and a `libghostty_vt::Terminal` per attached terminal driven by `RenderState` (ADR-0013).
- **`phux-mcp`** — thin adapter exposing the `phux-client` agent verbs (resolve, snapshot, run, wait) as MCP tools so any MCP-aware host can drive terminals.
- **`phux-config`** — TOML schema \\+ loader with `line:col` errors; keybind parser/trie resolver; status `Widget` trait \\+ time / session-name widgets.

## On the roadmap

- **`phux-client-gui`** — native GUI consumer over libghostty's surface API. Renders terminals its own way; shares no chrome with the TUI.
