**phux** is a libghostty-backed terminal control plane. A long-lived server hosts terminals — spawned, observed, controlled, persisted, addressable across hosts. A human's TUI and an agent's API are **peer consumers** of the same terminal: neither is privileged, and both ship today.

> "Need to replace tmux with a libghostty-based multiplexer so it can understand KIP." — Mitchell Hashimoto

## What makes it different

- **libghostty end-to-end.** Both server and client run `libghostty_vt::Terminal`. Nothing in the middle re-parses VT — modern terminal protocols (Kitty keyboard, true colour, OSC 8, OSC 133, images) pass through.
- **Asymmetric wire.** Server → client _content_ is **VT bytes** (per-client capability-rewritten); client → server _input_ is **structured key, mouse, focus, and paste events** built from libghostty's own atoms.
- **Layered protocol.** **L1 Terminal** is the substrate every consumer speaks; **L2 Collection** is an optional lifecycle bundle; **L3 Metadata** is an opaque KV store. Conformance is per-tier — an agent speaks L1 alone and never hears "session" or "window."
- **Federation-ready identity.** `TerminalId` is a `LOCAL` / `SATELLITE { host, id }` tagged union from day one. The wire bytes don't change when hubs route to satellites.
- **Agent surface in the box.** Headless CLI verbs (`ls`, `run`, `wait`, `watch`, `send-keys`, `snapshot`, `new`, `kill`, `rename`, `config`) ship alongside the TUI, and `phux-mcp` exposes the same core verbs as MCP tools over JSON-RPC.

## Status

**v0.1.** The TUI (attach, splits, status bar, keybindings, multi-client attach) and the headless agent surface (CLI verbs + `phux-mcp`) ship today. Federation routing — the `SATELLITE{host, id}` half of the wire — is accepted but not yet forwarded. The typed Rust SDK crate is convenience on top of surfaces that already work.

See the [VISION](https://github.com/phall1/phux/blob/main/VISION.md) for the long arc.
