phux is built with Rust and uses a Nix dev shell for reproducible toolchains.

## Enter the dev shell

```bash
nix develop          # or `direnv allow` once, then auto
```

The shell pins Rust 1.90, includes `zig_0_15` for libghostty-vt builds, plus `nextest`, `deny`, `watch`, `insta`, `mutants`, and `just`.

## Build and check

```bash
just check           # type-check across the workspace
just ci              # everything CI must pass
```

## Run

The binary ships with tmux-style auto-spawn. The server listens on a UDS at `$XDG_RUNTIME_DIR/phux/phux.sock`.

```bash
phux server          # start the daemon
phux attach          # attach the TUI client
```

## Create a named session

`phux new` creates a session and attaches to it. The first positional argument is the **session name**, not a command to run.

```bash
phux new work        # create and attach to a session named "work"
phux new -s work     # same thing, flag form (required with --json)
phux new             # auto-name from the session-name-template
```

To seed the first pane with a command instead of the default shell, pass it after `--`:

```bash
phux new web -- htop
```

A name that already exists is an error — use `phux attach <name>` to join an existing session.

## Philosophy

phux aims to be [**smol**](https://smol.tauri.app/): a well-defined problem, a single maintainer, programs that compose, programs that can be finished. See `CONTRIBUTING.md` for the things we say no to.
